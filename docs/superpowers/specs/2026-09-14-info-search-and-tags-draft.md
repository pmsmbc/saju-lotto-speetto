# 꿈해몽 글 검색·분류 기능 개발초안

작성일: 2026-09-14
대상 화면: `/info` (꿈해몽·상식 글 목록)
상태: **초안 — 구현 전, 방향 확정 필요**

## 1. 현황 (코드 확인 완료)

| 항목 | 현재 값 |
|---|---|
| 전체 글 | 62편 (꿈해몽 54 + 사주·로또 상식 8) |
| 분류 체계 | 2단 (`dream` / `guide`) 뿐 |
| 목록 UI | 선택 카테고리의 **전체 글을 한 줄로 나열** (`InfoPage.jsx` 하단) |
| 검색 | 없음 |
| 정렬 | `order` 오름차순 고정 (글 추가 순 = 사실상 등록순) |
| 글 적재 | `articles.js`의 `import.meta.glob(..., eager: true)` — 빌드 시 번들에 전량 포함 |

`/info` 진입 시 꿈해몽 탭에서 54개 카드가 한 화면에 쭉 나열된다. 모바일 기준 스크롤이 매우 길고,
원하는 꿈을 찾으려면 눈으로 훑는 방법밖에 없다. 글이 늘수록 선형으로 악화된다.

### 1-1. 번들 크기 (같이 발견한 문제)

글 본문 전체가 JS 번들에 들어간다. 운세만 보러 온 방문자도 62편 전문을 내려받는다.

| 시점 | 글 수 | 번들(raw) |
|---|---|---|
| 2026-09-08 | 47편 | 254 KB |
| 2026-09-14 | 62편 | 348 KB |

글 1편당 약 6 KB씩 증가한다. 현재 번들 348 KB 중 글 원문이 129 KB(gzip 39 KB)로 **약 37%**를 차지한다.

또한 `parseArticle()`이 `body`(마크다운 원문)와 `html`(변환 결과)을 **둘 다** 반환하는데,
`body`는 앱 어디에서도 쓰이지 않는다 (`articles.test.js:33` 단언문이 유일한 참조).
즉 같은 내용이 번들에 두 번 들어 있다.

## 2. 목표

1. 방문자가 **찾고 싶은 꿈을 몇 초 안에** 찾을 수 있게 한다.
2. 글이 100편이 되어도 목록이 무너지지 않는 구조를 만든다.
3. 분류 자체를 **검색 유입 경로**로 쓴다 (태그별 페이지 = 신규 색인 URL).

## 3. 분류 체계 제안

### 3-1. 단일 카테고리 vs 다중 태그

| | 단일 카테고리 | 다중 태그 (제안) |
|---|---|---|
| 구현 | 간단 | 배열 파싱 필요 |
| 애매한 글 | 피 꿈 = 몸? 재물? **하나만 골라야 함** | 둘 다 부여 가능 |
| 발견 경로 | 1개 | 여러 개 |
| 위험 | 분류가 부자연스러워짐 | 태그 남발 시 의미 희석 |

**다중 태그를 권장한다.** 꿈 소재는 본래 여러 의미가 겹친다(피 = 몸 + 재물, 꽃 = 자연 + 태몽).
단일 분류로는 반드시 부자연스러운 자리가 생긴다.

### 3-2. 태그안 (꿈해몽 54편 실제 배정 기준)

| 태그 | 편수 | 예시 |
|---|---|---|
| 동물 | 19 | 돼지, 뱀, 용, 호랑이, 고양이, 거미 … |
| 재물·돈 | 9 | 똥, 돈, 금·보석, 물고기, 도둑 |
| 불안·악몽 | 9 | 쫓김, 시험, 귀신, 추락, 군대, 화장실 |
| 사람·관계 | 7 | 조상, 연예인, 옛 애인, 결혼, 키스, 싸움 |
| 태몽·임신 | 6 | 태몽 총정리, 과일/동물 태몽, 임신, 아기, 꽃 |
| 자연·날씨 | 5 | 물, 불, 비, 눈, 꽃 |
| 몸·변화 | 5 | 이빨, 머리카락, 피, 나는 꿈, 우는 꿈 |
| 생활·사물 | 3 | 신발, 이사, 집 |

합계가 54를 넘는 것은 정상이다 (꽃 = 자연 + 태몽처럼 중복 배정).

**확정 필요:** 위 8개 태그 이름과 배정은 제안일 뿐이다. 특히 아래는 판단이 갈린다.
- `불안·악몽`이라는 이름 — 방문자에게 부정적으로 읽힐 수 있음. `심리·불안` 등 대안 검토
- 죽는 꿈: 불안으로 볼지, 별도 `길몽 반전` 묶음으로 볼지
- `생활·사물` 3편은 태그로 세우기엔 적음 — 글이 더 쌓일 때까지 보류 가능

### 3-3. 데이터 표현

frontmatter에 한 줄 추가한다. 기존 파서(`markdown.js`의 `parseArticle`)가 `key: value`를 그대로
문자열로 넣으므로, **쉼표 구분 문자열**이 가장 손이 덜 간다.

```
---
title: 꽃 꿈 해몽 — 활짝 핀 꽃이 알리는 소식
slug: flower
tags: 자연·날씨, 태몽·임신
order: 54
---
```

`articles.js`에서 `tags`를 배열로 갈라 넣는다. 태그가 없는 글은 빈 배열로 두어
기존 62편을 한꺼번에 고치지 않아도 동작하게 한다.

## 4. 기능 설계

### 4-1. 검색

**전량 클라이언트 검색으로 충분하다.** 이미 모든 글이 번들에 들어 있어 별도 색인 파일이나 API가 필요 없다.

- 대상: 제목 + 설명 + 본문
- 정규화: 공백 제거 후 비교 (`돼지꿈` ↔ `돼지 꿈` 모두 매치)
- 정렬: 제목 일치 → 설명 일치 → 본문 일치 순
- 결과 없을 때: 인기 글 또는 전체 목록으로 안내

초성 검색(`ㄷㅈ` → 돼지)과 형태소 분석은 **1차 범위에서 제외**한다. 한글 초성 분해는 구현 가능하지만
62편 규모에서 체감 이득이 작고, 오탐이 늘어난다.

### 4-2. 목록 화면

```
┌─────────────────────────────┐
│  [꿈해몽] [사주·로또 상식]      │  ← 기존 카테고리 탭 유지
│  ┌───────────────────────┐  │
│  │ 🔍 어떤 꿈을 꾸셨나요?    │  │  ← 신규: 검색 입력
│  └───────────────────────┘  │
│  (전체) 동물 재물·돈 불안·악몽 │  ← 신규: 태그 칩 (가로 스크롤)
│   사람·관계 태몽·임신 …        │
│                             │
│  [글 카드] …                  │  ← 기존, 필터 결과만 표시
└─────────────────────────────┘
```

- 검색어와 태그는 **AND**로 동작 (동물 태그 + "물" 검색 = 물고기 등)
- 선택 상태는 URL 쿼리에 반영 (`/info?tag=동물&q=물`) — 공유·뒤로가기 대응
- 결과 건수를 칩 옆이나 목록 위에 표시

### 4-3. 태그별 SEO 페이지

`/info/tag/animal/` 형태의 정적 페이지를 태그마다 생성한다. 현재 `make-routes.js`가
글·기능 페이지를 미리 렌더하는 구조가 이미 있으므로 같은 방식으로 붙인다.

- 제목 예: `동물 꿈 해몽 모음 19편 — 뱀·돼지·용·호랑이 | 사또`
- 본문: 태그 설명 문단 + 해당 글 전체 링크 목록
- sitemap 추가 → 색인 URL 8개 증가

URL의 태그 부분은 영문 슬러그를 쓴다 (`animal`, `money`, …). 한글 URL은 인코딩되어 지저분해진다.
따라서 태그 정의는 `{ id: 'animal', label: '동물' }` 형태의 목록이 별도로 필요하다.

## 5. 구현 단계

각 단계가 독립적으로 배포 가능하도록 나눈다.

### 1단계 — 태그 데이터 + 필터 (반나절)

| 파일 | 작업 |
|---|---|
| `content/dreams/*.md` | frontmatter에 `tags:` 추가 (54편) |
| `src/lib/tags.js` (신규) | 태그 목록 정의(id/label/설명), 글→태그 헬퍼 |
| `src/lib/articles.js` | `tags` 문자열 → 배열 변환 |
| `src/pages/InfoPage.jsx` | 태그 칩 UI, 필터 상태 |
| `src/App.css` | 칩 스타일 (기존 `.game-tab` 재사용 가능) |

### 2단계 — 검색 (반나절)

| 파일 | 작업 |
|---|---|
| `src/lib/search.js` (신규) | 정규화·매칭·점수 정렬 순수 함수 |
| `src/pages/InfoPage.jsx` | 검색 입력, URL 쿼리 동기화 |

`search.js`를 순수 함수로 빼면 테스트가 쉽다. 기존 `seo-pages.js`와 같은 방식이다.

### 3단계 — 태그별 정적 페이지 + 번들 정리 (반나절)

| 파일 | 작업 |
|---|---|
| `scripts/seo-pages.js` | `tagPages()` 추가 |
| `scripts/make-routes.js` | 태그 페이지 생성 + sitemap 등록 |
| `src/App.jsx` | `/info/tag/...` 경로 분기 |
| `src/pages/InfoPage.jsx` | 태그 경로로 진입 시 해당 태그 선택 상태로 시작 |
| `src/lib/markdown.js` | `parseArticle`에서 `body` 제거 (번들 절감) |

## 6. 주의점 (과거에 실제로 밟은 지뢰)

1. **경로 정규식이 세 군데에 흩어져 있다.** 새 URL 패턴을 추가하면 다음을 모두 고쳐야 한다.
   - `src/App.jsx` `stateFromPath()`
   - `src/pages/InfoPage.jsx` `slugFromPath()`
   - `scripts/make-routes.js` (정적 파일 생성)
   2026-09-10에 `taemong-fruit` 슬러그를 추가했을 때 `slugFromPath()`의 `[a-z]+`가 하이픈을
   못 받아 글이 열리지 않는 버그가 났다. 같은 실수가 반복되기 쉽다.

2. **`body` 제거 시 테스트 수정 필요.** `articles.test.js:33`이 `a.body.length`를 단언한다.

3. **태그 이름에 `·`를 쓰면** URL 슬러그와 표시 라벨을 반드시 분리해야 한다 (5절 참고).

4. **정적 렌더 내용과 React 렌더 내용이 어긋나면 안 된다.** 태그 페이지를 미리 렌더해 놓고
   React가 다른 목록을 그리면 방문자가 깜빡임을 본다. 진입 시 태그 선택 상태를 URL에서 복원해야 한다.

## 7. 범위 밖 (지금은 하지 않음)

- 초성 검색, 오타 교정, 형태소 분석
- 조회수·인기순 정렬 (집계 수단이 없음. GA 연동은 별건)
- 글 본문 지연 로딩 (번들이 더 커지면 그때 검토)
- 댓글·즐겨찾기 등 방문자 데이터 저장 (백엔드 필요)

## 8. 확정이 필요한 것

1. 태그 8개의 이름과 배정 (3-2절) — 특히 `불안·악몽` 명칭
2. `생활·사물`(3편)을 지금 세울지, 글이 더 쌓일 때까지 보류할지
3. 3단계(태그별 SEO 페이지)까지 갈지, 1~2단계만 할지
4. 검색 입력을 항상 보이게 할지, 돋보기 아이콘을 눌러야 열리게 할지
